# Decisions
- D1 Mod id stays `emi` (27 plugins, 16 mods using internals, 5 mixing in). Name "EMI Remastered", version `2.0.0+1.21.1` (must stay >= 1.1.24 for `emi` version ranges), jar `EMIRemastered-1.21.1-2.0.0-Fabric.jar`. fabric.mod.json `provides` the 7 add-on ids so a leftover add-on jar fails loudly.
- D2 One plain Fabric Loom project, Yarn mappings, Java 21; xplat+fabric sources merged into `src/main`; neoforge/forge dropped. `EmiAgnosFabric` and all `dev.emi.emi` names/members kept (Sporran mixin, internal users).
- D3 Add-ons become modules under `dev.emi.remastered.<module>`; each keeps its resource namespace (emi_loot, emiffect, ...) so resource packs and data still apply. Distraction Free Recipes is built into EMI core (no mixins into own classes).
- D4 One config: every module setting lives in EMI's own config system/screen; fzzy_config, txnilib, Architectury, ForgeConfigAPIPort dropped as dependencies.
- D5 Mojang-mapped add-ons are converted to Yarn with Loom `migrateMappings` before integration.
- D6 Porting agents never edit the access widener (single file); they use mixin accessors/invokers. EMI Loot's port owns the AW merge.
- D7 Parallel code agents run in separate git worktrees; the lead merges.
- D8 Duplicates: own modules stay on; plugin manager lets the player switch off any EMI plugin by mod id; Let's Do module skips categories the native plugin already registers.
- D9 Tests: JUnit 5 (test scope only) for pure logic; dev-client screenshot tour; final pack run under the game lock.
- D10 Translations: en_us + de_de for all new strings.
- D11 Parallel code agents get a worktree the lead creates from `remastered` (Agent isolation worktrees start from `main`).
- D12 Game sound always off: every client launch with `soundCategory_master:0.0` (owner request); prepareDevOptions enforces it (Q1b).
- D13 Dev clients never take the owner's mouse: no computer-use/OS input by agents; dev-only no-grab/no-focus mixin in the devtour mod on every client run config; client checks batched into tour runs (owner request).
- D14 Enchanted books above the listed range (> max+5 or > 10) do not open the enchantment page: a level-ignoring lookup would need an EMI core comparison change for all enchanted books (side effects); accepted limitation.
- D15 Until FOCUS1 is merged no agent except the FOCUS1 agent starts a dev client (T1-1: window still takes OS focus on Windows); gated agents finish code/build/server first and get a go message after the merge (owner focus rule).
- D16 Pack check without the owner: the lead does not launch the real pack instance (owner decision + agent rule); compatibility is shown by a pack-mirror dev client (copied mods, hidden, muted) and a production dedicated server with copied mods. The owner's own launch stays the final check.
- D17 Precision override: PACK-CLI and LOGO go to Opus (telling dev-remapping artefacts from real mixin incompatibilities; visual design quality the owner sees first). Budget stays ~20 % Opus.
- D18 Structure lookup results are delivered asynchronously (sent when ready) instead of the server thread waiting up to 30 s; found in the real pack (join blocked ~24 s). Opus (concurrency on the network path).
- D19 PACK-REAL2 runs in parallel with POLISH on the current build (POLISH only changes client display; LOOT-ASYNC is what needs the real pack); the final jar is copied in afterwards without a third launch. Opus as precision override (owner's real instance and data).
- D20 Session 8 follow-ups (owner-approved optional polish): X-PAD and X-SUMMARY to Sonnet, X-PARALLEL to Opus as precision override (concurrency in the server-side lookup: same results, cancellation, no leaked threads). Each in its own worktree from `remastered`; X-SUMMARY touches only the summary block of `StructureLookup.run`, X-PARALLEL only scan/template reads, so both merge cleanly.
- D21 Extra sources come from client RESOURCE packs (`assets/*/emi_sources`), like EMI's own customisation files: no networking, works in multiplayer; plugin registered via the `emi` entrypoint, never a mixin into our own EMI classes.
- D22 Search by source uses a new EMI query prefix `~` (enum constant appended, TOKENS regex extended, marked); labels from producing recipes + optional `SourceLabels` interface; `~nosource` = cheap equivalent of the Item Info marker (differences documented in docs/SEARCH.md).
- D23 One-key item view keeps EMI's RecipeScreen and R/U (other mods call displayRecipes/displayUses, four pack mods mix into EMI screens); a tab bar Info | Recipes | Uses joins RecipeScreen and InfoScreen via mixins only; EMI terms instead of "How to Get/Used For" (those stay as Info sections). Opus as precision override (UI hooks shared with ali/CQA/hollowhorizon).
- D24 Mob stacks use the namespaced serializer type `emi_mobs:mob` (EMI types are global strings).
- D25 Performance work must prove identical output (dump + search comparison); X-PERF2 skipped remainder caching (5 pack mods mix into recipe/remainder classes), professions caching (no complete key) and moving item groups off the render thread (vanilla contract). X-PERF/X-PERF2 to Opus as precision overrides.
- D26 Structure lookup cache: one file in the game dir (`emi_remastered/cache/structure-lookup.dat`) holding only the jigsaw walks (structure -> loot tables); dimensions, code-placed chests and table references are recomputed live every build, so biomes/loot tables/chest list need no fingerprint and worlds share the file. Fingerprint = format, mods (id, version, origin file path/size/mtime), data packs in order (mod jar, zip size+mtime, directory structure files, unknown pack classes by template content), structures (type, start pool), pools (elements); any input file newer than JVM start = no read/write; builds with failed walks are not saved. Pack: hit ~200 ms vs walk ~1.5 s, 54 KB. Opus as precision override: a stale cache shows wrong 'Found in' silently.
- D27 LOGO2 to Opus as precision override (owner asked for true pixel art; visual craft is the deliverable, like D17).
- D28 Clean repo (owner: "all under mc/1.21.1 branch", "clean github repository"): `remastered` renamed to `mc/1.21.1` (owner's convention, as in FramedBlocks-Fabric) and made the GitHub default; old `main` (upstream EMI 1.1.24, an ancestor of mc/1.21.1, so no history lost) deleted on GitHub and locally; merged wip/* branches deleted. Upstream history and credits stay in the branch.
- D29 Readable text on recoloured panels: a pack-overridable colour REMAP table `assets/emi_remastered/text_colors.json` (`{"replace": {"404040": "FFFFFF", ...}}`, RGB hex, merged over all packs, higher pack wins per key; mod ships it empty, so no visible change without a pack). Applied at EMI's two text funnels (TextWidget.render, EmiDrawContext text draws) plus our ~13 raw DrawContext.drawText sites, for the int colour AND colours baked into Text styles. Reason: one hook also fixes third-party EMI plugins that use the same vanilla greys; roles per site would need ~90 edits and miss other mods. Tooltips untouched. Mod version 2.1.0 (new pack-facing feature), pack 2.2.0.
- D30 Pack mapping on Nytheria blue: dark greys/black -> #FFFFFF, mid greys -> #9FA5A6, disabled -> #899094, dark link/Formatting hues (DARK_BLUE/RED/GREEN/PURPLE, BLUE, link blues, 8B0000) -> light versions of the same hue (they are unreadable on #326089 otherwise). Gold/green/red already light stay.
- D31 Pack fixes found by MAP2 go in with 2.2.0: empty-sidebar icon region of emi widgets.png (transparent in the pack) and background.png corner alpha; emi_loot restyle recipe points at the EMI Remastered jar.
